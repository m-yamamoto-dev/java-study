# クラスとインスタンスとは

**クラス**は、オブジェクトの状態や操作を定義するものです。クラスから作られた個々のオブジェクトを、そのクラスの**インスタンス**と呼びます。

## 要点

- フィールドは状態、メソッドは操作を表します。
- コンストラクタは新しいインスタンスを初期化します。
- `this`は、現在のインスタンスへの参照です。
- カプセル化は、内部の状態と操作をまとめ、外部からの扱い方を制限する考え方です。

## 仕組み・特徴

### コンストラクタ

通常のクラスでは、コンストラクタはクラスと同じ名前で、戻り値の型を指定しません。コンストラクタを一つも宣言しなければ、引数なしのデフォルトコンストラクタが暗黙に宣言されます。自分でコンストラクタを宣言した場合は、この自動追加はありません。

デフォルトコンストラクタは、通常、スーパークラスの引数なしコンストラクタを呼びます。スーパークラスにアクセス可能で`throws`節のない引数なしコンストラクタがなければ、コンパイルエラーになります。その場合は、適切なスーパークラスのコンストラクタを呼ぶコンストラクタを自分で宣言します。

### フィールド初期化と実行順序 {#initialization}

インスタンスのフィールドには、最初に型に応じた既定値が入ります。一般的な、`super(...)`を先頭に書くコンストラクタでは、スーパークラスの初期化後に、そのクラスのインスタンスフィールド初期化子とインスタンス初期化ブロックがソース上の順序で実行され、続いてコンストラクタの残りの処理が実行されます。`this(...)`で別のコンストラクタへつないでも、同じインスタンスのこれらの初期化子が繰り返し実行されるわけではありません。

Java 25では、制約の下で`super(...)`や`this(...)`より前に処理を書けます。そのため、「コンストラクタの処理はすべてフィールド初期化の後」とは限りません。staticフィールドの初期化はインスタンス作成ごとではなく、クラスの初期化に属します。

### アクセス修飾子とカプセル化 {#access}

`private`で状態へのアクセスを制限し、公開した操作を通して状態を扱うと、不正な値を防ぎやすくなります。すべてのフィールドにsetterを作ることがカプセル化ではありません。

| 修飾子 | 基本的なアクセス範囲 |
| --- | --- |
| `public` | 広く公開。モジュールなどによる制限も受ける |
| `protected` | 同じパッケージとサブクラス。別パッケージからのアクセスには制約がある |
| 指定なし | 同じパッケージ |
| `private` | その宣言を囲むトップレベルクラスの内部 |

## コード例

```java
class Counter {
    private int value;

    Counter(int value) {
        this.value = value;
    }

    void increment() {
        value++;
    }

    int getValue() {
        return value;
    }
}
```

`new Counter(0)`で作る各インスタンスは、それぞれ自分の`value`を持ちます。`this.value`はフィールド、右側の`value`はコンストラクタの引数です。

## 間違えやすい点

- クラスの宣言とインスタンスの作成は別です。
- 参照変数を代入しても、インスタンスは複製されません。
- コンストラクタに`void`を付けると、コンストラクタではなくメソッドになります。
